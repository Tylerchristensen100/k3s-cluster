# Secrets

Policy: **no plaintext secret ever enters Git.** Secrets are encrypted with Sealed Secrets and committed as `*.sealed.yaml`; the in-cluster controller decrypts them. CI and `scripts/lint.py` reject any `kind: Secret` manifest, and require `*.sealed.yaml` files to contain only `SealedSecret`s. (The `!*.sealed.yaml` exception in `.gitignore` is **not** a safety net: a plain Secret saved under that name would still be staged.)

| Component | Where |
| --- | --- |
| Controller (`sealed-secrets-controller`, `kube-system`) | `infrastructure/sealed-secrets` (Helm chart via Fleet) |
| Seal-only web UI | `apps/sealed-secrets-web` -> `https://sealed-secrets-web.k3s-node.home` |
| Public cert (encrypt-only, safe to commit) | `certs/sealed-secrets-pub.pem` |
| CLI helper | `scripts/seal.sh` |

## Sealing a secret

Sealing needs only the **public** certificate, so no cluster access is required. Seals use `strict` scope: bound to the namespace **and** name, so a file can't be reused under another name.

- **Web UI:** open the URL above, enter namespace, name and key/values, and copy the output into `apps/<app>/<name>.sealed.yaml`. LAN-only, TLS from the internal CA, no auth, so don't expose it outside the LAN. Ignore any placeholder keys the form pre-fills (e.g. a sample `values.yaml`) and delete them from the output.
- **CLI** (needs `kubectl` + `kubeseal`, no kubeconfig): `scripts/seal.sh <ns> <name> apps/<app>/<name>.sealed.yaml KEY=VALUE [KEY=@file]`.

Before committing, check the file starts with `kind: SealedSecret` and has `encryptedData:`; then run `python scripts/lint.py`. After pushing, `scripts/check-cluster.sh` confirms the controller decrypted it (Synced). The plaintext you typed into the form must never be saved to disk.

Re-export the cert if the controller key is ever rotated or restored:

```sh
kubeseal --controller-name sealed-secrets-controller --controller-namespace kube-system --fetch-cert > certs/sealed-secrets-pub.pem
```

## Inventory

| Secret | Namespace | Contents | How it's managed |
| --- | --- | --- | --- |
| `messages-archiver` | `messages-archiver` | `UI_PASSWORD`, `drive_client_id`, `drive_client_secret` | Sealed in `apps/messages-archiver/secrets.sealed.yaml` |
| `github-app-auth` | `fleet-local` | GitHub App id, installation id, private key (read access to the private repo) | **By hand**, not in Git (bootstrap for Fleet itself) |
| `k3s-node-ca-secret` | `cert-manager` | Internal CA key | Generated by cert-manager; back it up ([runbook](runbook.md#back-up-the-ca-key)) |
| Sealed Secrets controller key | `kube-system` | Decrypts every sealed file | Generated by the controller; back it up ([bootstrap](bootstrap.md)) |
| `~/.ssh/messages-archiver-deploy` | on the node | Read-only deploy key for the private repo | On the node only |
| Home Assistant `.storage/*` | `home-assistant` PVC | Auth tokens, integrations | On the volume; covered only by HA backups |

If a secret is exposed (pasted, committed, shown in a log), rotate it at the source (e.g. reset the Google OAuth client secret), then re-seal. Removing it from Git history is not enough.
