# Secrets

No secrets exist yet, and none may be committed in plain text (`.gitignore` blocks common patterns). Decide on a mechanism before adding the first one (MQTT passwords, API tokens, etc.).

## Options

| Option | Notes |
| --- | --- |
| **Create by hand** | `kubectl -n <ns> create secret generic ...`. Simplest; not reproducible, so document each one here. |
| **Sealed Secrets** | Encrypt with `kubeseal`, commit the `*.sealed.yaml`; the in-cluster controller decrypts. Good fit for Fleet. |
| **SOPS + age** | Encrypt files in git; needs a decryption step Fleet doesn't do natively. |

**Chosen: Sealed Secrets**, installed by `infrastructure/sealed-secrets` (Helm chart via Fleet, controller `sealed-secrets-controller` in `kube-system`). Usage is in [runbook.md](runbook.md#sealed-secrets). Back up the controller key, or sealed files become unrecoverable after a rebuild.

## Sealing from any machine or the web UI

Sealing only needs the controller's **public** certificate, so no cluster access is required.

- **Public cert**: `certs/sealed-secrets-pub.pem` (committed; safe, encrypt-only). Export once with
  `kubeseal --controller-name sealed-secrets-controller --controller-namespace kube-system --fetch-cert > certs/sealed-secrets-pub.pem`
  (run where `kubectl` reaches the cluster, e.g. over SSH on the node). Re-export if the key is ever rotated or restored.
- **CLI, any computer** (needs `kubectl` + `kubeseal` installed, no kubeconfig): `scripts/seal.sh <ns> <name> apps/<app>/<name>.sealed.yaml KEY=VALUE`
- **Web UI**: `https://sealed-secrets-web.k3s-node.home` (`apps/sealed-secrets-web`, seal-only). Enter namespace, name, key/values; copy the output into `apps/<app>/<name>.sealed.yaml`. LAN-only, TLS via the internal CA, no auth, so don't expose it outside the LAN.
- Seals are `strict` scope: bound to namespace and name, so a file can't be reused under another name.
